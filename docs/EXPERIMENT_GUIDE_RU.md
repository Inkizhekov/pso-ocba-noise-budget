# Руководство по эксперименту PSO-OCBA

Версия документации: 25 октября 2026 года. Издание для минимального пакета.

В комплекте есть результаты всех поисков и три примера первичных журналов.
Полные трассы остальных заданий находятся в отдельном сохраненном полном архиве.
Команды новых научных поисков используют новый каталог результатов.

Это руководство объясняет исследование с нуля: что сравнивается, как устроен
код, как запустить проверку, где лежат данные и как читать результаты.
Оно описывает существующий проект и зафиксированный в проекте протокол.
Научные исходники, данные, статья и зафиксированные архивы при подготовке
руководства не изменяются.

PSO (Particle Swarm Optimization, алгоритм роя частиц) ищет хорошую точку
пространства параметров. OCBA (Optimal Computing Budget Allocation,
оптимальное распределение вычислительного бюджета) решает, какие точки стоит
измерить повторно, чтобы надежнее выбрать лучшие.

Все команды ниже рассчитаны на PowerShell в корне проекта. После распаковки
полного архива корнем считается каталог с `experiment.py`. Относительные
пути в командах отсчитываются от этого каталога.

Для версии GitHub сначала выполните `py -3.13 prepare_data.py` в корне. Это восстановит таблицу CSV, сжатую для загрузки через браузер; последующие команды и научные модули остаются прежними.

## 1. Главная идея на простом примере

Представим, что нужно подобрать настройки нейросети. Можно обучить много
разных вариантов по одному разу. Можно проверить меньше вариантов, но каждый
обучить несколько раз. Во втором случае оценка надежнее, зато поиск успевает
посетить меньше конфигураций.

Возникает дополнительный вопрос: если повторять измерения, надо ли делить
повторы поровну? Возможно, большая часть вариантов явно неудачна, а спорными
остаются только несколько близких кандидатов. Тогда полезно потратить
дополнительные измерения именно на них.

В эксперименте сравниваются эти решения при одинаковом общем количестве
вызовов функции качества. Проверяется конечный результат всего поиска,
а не только точность оценки одной заранее выбранной точки.

Учебный пример, не результат исследования: истинное качество A равно 0.80,
качество B равно 0.78. Из-за шума первое измерение может дать A = 0.77,
B = 0.85. Алгоритм, доверяющий единственному измерению, выберет B. Повторы
могут исправить выбор, но каждый повтор расходует бюджет, который можно
было потратить на новую точку C.

Вся работа посвящена этому компромиссу. Ее задача состоит в измерении
условий эффективности существующих методов. Новый оптимизатор здесь
не предлагается.

Полезно сразу различать три эффекта:

1. Польза повторов: сравнение PSO-OCBA с однооценочным PSO.
2. Польза адаптивного распределения: сравнение PSO-OCBA с равномерным PSO-EA.
3. Польза учета личных рекордов в распределении: сравнение PSO-OCBA
   с PSO-OCBA-RS.

Победа в первом сравнении сама по себе ничего не доказывает о втором
или третьем.

<a id="units"></a>
## 2. Что именно считается запуском и бюджетом

| Понятие | Простое объяснение | Как представлено в коде |
|---|---|---|
| Точка | Один набор параметров | Вектор `x` в `[0, 1]^d` |
| Измерение | Один шумный вызов функции в точке | Одна строка `evaluations.csv.gz` |
| Повтор | Еще один вызов в той же точке | Увеличение `Pool.count` |
| Частица | Участник роя со своей позицией и скоростью | Строка массивов `positions`, `velocities` |
| Поколение | Один цикл оценки текущих позиций и обновления рекордов | Поле `generation` |
| Поиск | Весь запуск одного метода с одним случайным зерном и бюджетом | Одна строка `runs.csv` |
| Случайное зерно, seed | Число, задающее воспроизводимую последовательность случайных чисел | `seed`, `master_seed` |
| Условие, ячейка | Фиксированное сочетание задачи, шума, бюджета и роя | Словарь задания `job` |
| Рабочее задание, job | Единица, передаваемая отдельному процессу | Каталог с `complete.json` |
| Парный запуск | Результаты разных методов, сопоставленные по одному номеру случайного запуска | Одинаковый `run` внутри условия |
| Бюджет B | Разрешенное число поисковых измерений | `budget`; фактически использованное число - `calls` |
| Размер роя M | Число частиц | `swarm`, аргумент `swarm_size` |
| Начальные повторы n0 | Число стартовых измерений каждой новой позиции для методов с повторами | `initial_repeats` |

В основной синтетической серии одно рабочее задание содержит четыре метода
по 30 поисков, всего 120 строк результатов. В нейросетевой серии одно
задание содержит три метода для одного номера запуска, всего три поиска.
Поэтому число заданий нельзя отождествлять с числом поисков.

В нейросетевой части один поисковый вызов означает одно обучение модели
с оценкой на проверочной выборке. После поиска выбранная конфигурация
обучается еще три раза для итоговой оценки. Эти три обучения учитываются
отдельно от B. Они не являются тремя независимыми поисками.

Одинаковый B означает одинаковое число поисковых вызовов. Он не означает
одинаковое число арифметических операций, время работы или энергозатраты.
Например, обучение широкой сети может стоить дороже обучения узкой.

<a id="methods"></a>
## 3. Четыре сравниваемых метода

| Название | Идентификатор | Что происходит с измерениями |
|---|---|---|
| PSO | `pso` | Каждая новая позиция измеряется один раз |
| PSO-EA (Equal Allocation, равномерное распределение) | `pso_ea` | После начальных повторов используется равномерное целевое распределение |
| PSO-OCBA-RS (Ranking and Selection, ранжирование и выбор лучшего) | `pso_ocba_rs` | Обычная OCBA направляет повторы на выбор лучшего кандидата |
| PSO-OCBA | `pso_ocba` | Распределение дополнительно учитывает сравнения с личными рекордами частиц |

У всех четырех методов общая логика движения роя и одинаковые коэффициенты
движения. Существенное различие находится в оценивании и распределении
повторов. Общий движок позволяет контролировать это различие.

`pbest` (personal best, личный рекорд) - сохраненная лучшая позиция конкретной
частицы по накопленному выборочному среднему. `gbest` (global best,
глобальный рекорд) - лучший из сохраненных личных рекордов по тому же
правилу. При шуме выбранный рекорд может не быть лучшим по истинному качеству.

В методах с повторами исходный бюджет полного поколения равен `6*M`.
Сначала каждая новая позиция получает `n0 = 3` измерения. Остаток распределяется
порциями по M измерений. В список кандидатов, кроме новых позиций, входит
сохраненный глобальный рекорд, если он уже существует.

Уточнение про EA: равномерными являются целевые накопленные количества
измерений кандидатов. Старые наблюдения глобального рекорда сохраняются.
Поэтому реализация не сводится к правилу "ровно шесть новых измерений
для каждой частицы в каждом поколении".

Учебный расчет для `M = 12`, `B = 540`:

- PSO расходует 12 измерений на полное поколение и получает 45 поколений.
- Методы с повторами расходуют 72 измерения на полное поколение.
  Получается семь полных поколений и последнее неполное: `7*72 + 36 = 540`.
- На старте полного поколения 36 измерений уходят на `12*3` начальных
  наблюдений. Еще 36 доступны для последующего распределения.

Более надежная оценка уменьшает число шагов поиска. Именно поэтому повторы
могут как помогать, так и вредить.

Исторический PSO-R3 использует три равномерных измерения новой позиции.
Исторический PSO-AR (Adaptive Resampling, адаптивные повторы) является
отдельной эвристикой повторного оценивания.
Эти названия не являются синонимами PSO-OCBA; в четырехметодную основную
сетку они не входят.

<a id="synthetic"></a>
## 4. Синтетические задачи и модели шума

### 4.1. Зачем нужны задачи с известным ответом

Для нейросети истинное ожидаемое качество конфигурации заранее неизвестно.
На аналитической функции можно отдельно вычислить истинное качество и
добавить контролируемый шум. Тогда видно, нашел ли оптимизатор хорошую
точку или просто выбрал случайно завышенное наблюдение.

Истинное качество используется для итоговой оценки и диагностики ошибок.
Решения о распределении измерений и обновлении рекордов принимаются
по наблюдениям. Знание истинного ответа не передается в правило выбора.

Используются восемь функций: Sphere, Ellipsoid, Rosenbrock, Ackley,
Rastrigin, Griewank, Levy и Zakharov. Их реализации находятся в
[`ocba_benchmarks.py`](../ocba_benchmarks.py). В основной расширенной серии
размерность `d = 8`.

Область поиска - единичный куб. Перед вычислением исходной функции точка
сдвигается, поворачивается и масштабируется. Положение оптимума и матрица
поворота воспроизводимо задаются зерном конструкции задачи.

### 4.2. Почему хорошее качество может быть отрицательным

Движок максимизирует качество. Обычные тестовые функции минимизируются,
поэтому они преобразованы:

```text
z = (x - optimum) @ rotation * span
Q_true(x) = -max(0, raw_loss(z)) / calibration_scale
Q_observed(x) = Q_true(x) + eta * (0.6 + 0.8*x[0]) * Z
regret(x) = -Q_true(x)
```

`calibration_scale` - выборочное стандартное отклонение исходных значений
на 4096 равномерно выбранных калибровочных точках. Для разных функций
используются свои масштабы, зафиксированные конструкцией задачи.

Оптимальное истинное качество равно 0. Значение -0.01 лучше, чем -0.30.
Сожаление, regret (потеря относительно оптимума), наоборот, тем лучше,
чем его положительная величина ближе к нулю: 0.01 лучше 0.30.
Шумное наблюдение может быть положительным, хотя истинный максимум равен 0.

Порог 0.02 относится к нормированному качеству. Он не измеряется
в процентах accuracy (доли правильных ответов) и не является
универсальной практической величиной для любой задачи.

### 4.3. Что меняется в шуме

Четыре распределения Z стандартизованы: математическое ожидание 0,
дисперсия 1 до умножения на пространственный масштаб.

| Идентификатор | Формула Z | Проверяемая особенность |
|---|---|---|
| `gaussian` | `N(0, 1)` | Нормальный шум |
| `student_t3` | `t(df=3)/sqrt(3)` | Тяжелые хвосты; четвертого момента нет |
| `lognormal` | `(exp(N(0,1))-exp(0.5))/sqrt(e*(e-1))` | Асимметрия и тяжелый правый хвост |
| `contaminated` | Нормальная смесь с вероятностями 0.95 и 0.05, стандартными отклонениями 1 и 10; деление на `sqrt(5.95)` | Редкие крупные выбросы |

Смесь означает случайный выбор одного компонента при каждом измерении,
а не сумму двух независимых нормальных величин с весами 0.95 и 0.05.

Множитель `eta*(0.6 + 0.8*x[0])` делает шум гетероскедастическим
(его дисперсия зависит от положения точки). При фиксированных x и eta
первые два момента одинаковы у четырех моделей. Разные методы посещают
разные точки, поэтому фактическая совокупность полученных ими наблюдений
не обязана иметь одинаковую дисперсию.

OCBA продолжает использовать гауссову модель оценивания. Ненормальный
шум служит стресс-тестом этой модели. Алгоритм не распознает семейство
распределения и не переключается на специальную модель тяжелых хвостов.

### 5.1. Основная расширенная сетка

Параметры заданы в [`run_robust_ocba_study.py`](../run_robust_ocba_study.py):

| Параметр | Значения |
|---|---|
| Функции | Восемь перечисленных выше |
| Размерность | 8 |
| Размеры роя M | 6, 12, 24 |
| Бюджеты B | 540, 2160, 8640 |
| Уровни ненулевого шума eta | 1, 2 |
| Распределения ненулевого шума | Четыре |
| Контроль без шума | Только `gaussian`, `eta = 0` |
| Методы | PSO, PSO-EA, PSO-OCBA-RS, PSO-OCBA |
| Поисковые повторы на метод и условие | 30 |
| Начальные измерения n0 | 3 |

Число условий шума равно `1 + 4*2 = 9`. Нулевой шум не дублируется
четыре раза: при нуле форма распределения не несет информации.

```text
Задания = 8 * 9 * 3 * 3 = 648
Поиски = 648 * 4 * 30 = 77760
Поисковые оценки = 8 * 9 * 3 * 4 * 30 * (540 + 2160 + 8640)
                 = 293932800
```

### 5.3. Что запускает experiment.py

Основной вход [`experiment.py`](../experiment.py) управляет расширенной
синтетической серией, новым нейросетевым пилотом, расчетом объема,
независимой проверкой мощности, подтверждающей нейросетевой серией и их
основным анализом.

Абляция n0, новые экземпляры, исследовательские контрасты средних,
диагностика трасс и исторические серии имеют отдельные команды.
Таким образом, `experiment.py` без аргументов не означает автоматическое
повторение всех 126720 поисков всей истории статьи.


`py -3.13` выбирает установленную ветку 3.13; точную подверсию показывает
`--version`. Для наиболее близкого повторения используйте 3.13.3.
Создавайте `.venv`, если такого окружения еще нет. Уже настроенное рабочее
окружение пересоздавать не требуется.

Активация окружения необязательна: в примерах Python вызывается по полному
пути внутри `.venv`. Это также позволяет избежать ограничений PowerShell
на запуск скрипта `Activate.ps1`.

В авторской рабочей копии используется `.review_venv` с зафиксированными
научными версиями. Для него в приведенных командах замените только `.venv`
на `.review_venv`. В архив окружения Python не включаются.

### 6.3. Данные и ресурсы

Для новой нейросетевой серии нужны локальные файлы:

```text
datasets/uci/ionosphere.csv
datasets/uci/sonar.csv
datasets/uci/manifest.json
```

Они включены в этот минимальный пакет. Перед запуском нейросетевых фаз проверяются
их SHA-256 (Secure Hash Algorithm, контрольная сумма содержимого файла).

Если вы создаете новую рабочую копию без этих данных, предусмотрен загрузчик:

```powershell
.\.venv\Scripts\python.exe fetch_ocba_data.py
```

Он обращается к UCI (University of California, Irvine, репозиторий данных),
проверяет размер таблиц и формирует manifest. В неизменном пакете для
рецензента повторно запускать загрузчик не нужно: проверяйте уже включенные
данные, сохраняя их исходные байты и происхождение.

Количество процессов задается `--workers`. Основной вход использует
8 процессов для поисков и 6 для аудита, если параметры не указаны.
Численные потоки библиотек ограничиваются единицей, чтобы каждый рабочий
процесс не создавал еще один большой пул потоков.

Минимальный пакет содержит таблицы всех поисков и три контрольные трассы. Для пересчета этих данных не требуется распаковка прежнего полного архива.

<a id="main-run"></a>
## 7. Быстрая проверка и основной запуск

### 7.1. Сначала посмотреть план без вычислений

```powershell
.\.venv\Scripts\python.exe experiment.py --help
.\.venv\Scripts\python.exe experiment.py --dry-run --out results/my_study
```

`--dry-run` печатает JSON (JavaScript Object Notation, структурированный
текстовый формат) с фазами, параметрами и ожидаемым объемом. Он не создает
каталог результатов и не выполняет поиски.

Для полной основной сетки вывод должен содержать:

```json
{
  "synthetic_searches": 77760,
  "synthetic_calls": 293932800,
  "nn_pilot_searches": 432,
  "nn_main_runs_per_condition": "determined from independent pilot",
  "nn_main_searches": null
}
```

Это выбранные поля ответа, а не весь JSON. До появления проверенного
плана объем подтверждающей нейросетевой серии еще не известен. В серии
статьи получилось 456 запусков на метод и условие; это результат правила
планирования, а не число, которое следует вручную вписать вместо пилота.

### 7.2. Техническая проба

Smoke test (короткая техническая проверка запуска) проверяет работоспособность
движка на одном задании. Он не предназначен для научного вывода.

Сначала оцените его объем без вычислений:

```powershell
.\.venv\Scripts\python.exe experiment.py --smoke --dry-run --out results/my_study_smoke
```

Реальное выполнение технической пробы:

```powershell
.\.venv\Scripts\python.exe experiment.py --smoke --workers 1 --out results/my_study_smoke
```

По умолчанию это последнее синтетическое условие сетки, четыре метода,
один запуск каждого, B = 8640. Итого четыре поиска и 34560 измерений.
Флаг `--smoke` без явной фазы выбирает только `synthetic`.

Для отдельной нейросетевой технической пробы:

```powershell
.\.venv\Scripts\python.exe experiment.py --phase nn_pilot --smoke --workers 1 --out results/my_nn_smoke
```

Здесь выполняются три поиска по 540 поисковых обучений и три итоговых
обучения для каждого поиска. Это заметно дороже синтетической пробы.

В имени каталога технической пробы обязательно должно быть `smoke`.
Ее данные не подходят для фаз `plan`, `validate`, `nn_main` и `analyze`.
Для полного эксперимента нужен другой каталог.

### 7.3. Полный основной протокол

Следующая команда запускает большой научный расчет, включая нейросети:

```powershell
.\.venv\Scripts\python.exe experiment.py --out results/my_study --workers 8 --audit-workers 6
```

Каталог `results/my_study` должен быть новым либо уже принадлежать точно
этому протоколу. В текущем основном входе нет аргументов `--budget`,
`--runs`, `--noise` или `--dimension`: научная сетка зафиксирована в коде.

Порядок работы:

| Фаза | Что делает | Главный результат |
|---|---|---|
| `freeze` | Сохраняет параметры, контрольные суммы исходников и окружение | `protocol.json`, `runtime_environment.json` |
| `synthetic` | Выполняет расширенную аналитическую сетку | `synthetic_runs.csv` и первичные журналы |
| `nn_pilot` | Получает независимый пилот для планирования объема | `nn_pilot_runs.csv` |
| `plan` | Выбирает общий объем новой нейросетевой серии | `power_plan.json` |
| `validate` | Проверяет план мощности новой симуляцией | `power_validation.json` |
| `nn_main` | Выполняет подтверждающую серию новыми случайными зернами | `nn_main_runs.csv` |
| `analyze` | Проверяет первичные журналы и рассчитывает основной анализ | Таблицы, рисунки, `article_data.json` |

Сохранение и проверка протокола выполняются перед каждой отдельной фазой
также. Поэтому явный `freeze` удобен для просмотра, но для обычного полного
запуска не обязателен.

### 7.4. Запуск по фазам

Это альтернатива полной команде. Выполняйте строки последовательно:

```powershell
.\.venv\Scripts\python.exe experiment.py --phase freeze --out results/my_study
.\.venv\Scripts\python.exe experiment.py --phase synthetic --workers 8 --out results/my_study
.\.venv\Scripts\python.exe experiment.py --phase nn_pilot --workers 8 --out results/my_study
.\.venv\Scripts\python.exe experiment.py --phase plan --out results/my_study
.\.venv\Scripts\python.exe experiment.py --phase validate --out results/my_study
.\.venv\Scripts\python.exe experiment.py --phase nn_main --workers 8 --out results/my_study
.\.venv\Scripts\python.exe experiment.py --phase analyze --audit-workers 6 --out results/my_study
```

Запуск только `synthetic` не создает нейросетевой пилот. Для полного
`analyze` нужны все входные части основного протокола, включая план,
его валидацию и нейросетевые результаты.

Сохраненные результаты статьи находятся в каталогах с датой, перечисленных
в разделе 13. Новые расчеты направляйте в новый каталог. Для проверки прежнего зафиксированного выпуска исходники
сохранены в отдельном полном архиве от 24 октября.

<a id="resume"></a>
## 8. Остановка, возобновление и защита протокола

### 8.1. Что будет при остановке

Остановить команду можно сочетанием Ctrl+C. Завершенные задания сохраняются
в отдельных каталогах. Они отмечены `complete.json`, содержащим параметры
задания и контрольные суммы файлов.

Для продолжения повторите исходную команду с тем же `--out` и неизменными
научными исходниками. Число рабочих процессов можно уменьшить или увеличить:
оно не является параметром научной сетки.

При повторном запуске основной движок распознает завершенные задания
по `complete.json` и использует их результаты. Контрольные суммы
первичных файлов проверяются анализатором; сам факт пропуска задания
при продолжении не означает полного аудита его содержимого.
Незавершенное задание может быть рассчитано заново целиком.
Продолжение с середины отдельного поиска не реализовано.

Вывод прогресса и файлы `synthetic_progress.jsonl`, `nn_pilot_progress.jsonl`,
`nn_main_progress.jsonl` показывают завершение заданий. JSONL означает
последовательность JSON-объектов, по одному в строке. Длительности заданий
различаются; доля выполненных заданий не является точной оценкой
оставшегося времени.

При продолжении записи прогресса добавляются в конец файла. Уже готовое
задание может появиться в журнале повторно, поэтому сумму всех строк
прогресса нельзя использовать как окончательный счетчик исследования.
Для итогов нужны уникальные завершенные задания и таблицы поисков.

Не запускайте два независимых управляющих процесса одновременно в один
каталог `--out`. Параллелизм уже организован внутри одного запуска.

### 8.2. Зачем проверяются контрольные суммы

`protocol.json` связывает результат с конкретными параметрами и исходниками.
Если поменять движок или планировщик и продолжить в том же каталоге,
получится смесь разных экспериментов. Защита протокола останавливает
такую попытку.

Сообщение `Protocol, sources or smoke mode changed` означает, что текущие
исходники, сетка или технический режим не совпадают с сохраненными.
Для новой версии исследования выбирайте новый каталог. Для проверки прежних исходников
используйте сохраненный отдельный полный архив. Редактирование контрольных
сумм вручную разрушает связь данных с протоколом.

### 8.3. Почему план мощности нельзя пересчитывать после главной серии

После создания `power_plan.json` основной вход проверяет его и использует
повторно. В него включены контрольные суммы пилота, протокола и кода
планировщика. Главные наблюдения не должны влиять на выбор их количества.

Валидация мощности должна существовать до `nn_main`. Основной вход
откажется создавать отсутствующую валидацию, если каталог главных
наблюдений уже появился. Это сохраняет временной порядок исследования.

Отдельный `plan_robust_nn_power.py` при существующем плане завершится
ошибкой `Power plan is already frozen`. Для обычного продолжения
используйте `experiment.py`: он умеет безопасно использовать готовый план.

## 9. Дополнительные серии

Все команды реальных поисков в этом разделе создают дополнительные
вычисления. Они не выполняются автоматически при чтении или проверке
уже сохраненных таблиц.

### 9.1. Абляция n0

Абляция (контролируемое изменение одного элемента метода) проверяет
начальные повторы `n0 = 3, 5, 10`. Используются Ackley и Rosenbrock,
четыре шума, eta = 2, M = 12, B = 8640 и три метода с повторами.
Для каждого метода и условия выполняется 30 поисков.

Чтобы вариант n0 = 10 помещался в поколение, бюджет поколения равен `12*M`
во всех трех вариантах. Тогда у каждого поиска ровно 60 поколений.
Сравнение не подменяется разным количеством поколений.

```powershell
.\.venv\Scripts\python.exe run_n0_ablation.py --out results/my_n0_study --workers 8
.\.venv\Scripts\python.exe analyze_n0_ablation.py --out results/my_n0_study --audit-workers 6
```

Вторая команда читает и анализирует результаты в переданном каталоге.
Дополнительно нужен сохраненный мост к исходной серии:
`results/ocba_robustness_20261022/synthetic_runs.csv`. Он зафиксирован
в протоколе абляции. Это привязанный к статье сценарий, а не универсальный
анализатор произвольных сеток.

Первичные данные включают отдельный `initial_variances.csv.gz` для
начальных оценок дисперсии. Семья анализа содержит 72 контраста.

### 9.2. Новые экземпляры функций

Экземпляр - та же формула функции, но другое положение оптимума и поворот.
Проверяются два новых экземпляра каждой из восьми функций, всего 16.
Условия: d = 8, M = 12, B = 8640, eta = 2, нормальный и логнормальный шум,
методы EA, OCBA-RS и OCBA, 30 поисков на сочетание.

```powershell
.\.venv\Scripts\python.exe run_ocba_instance_validation.py --out results/my_instances --workers 8
```

По умолчанию выполняются фиксация плана, поиски и анализ. Их можно разделить:

```powershell
.\.venv\Scripts\python.exe run_ocba_instance_validation.py --phase freeze --out results/my_instances
.\.venv\Scripts\python.exe run_ocba_instance_validation.py --phase run --out results/my_instances --workers 8
.\.venv\Scripts\python.exe run_ocba_instance_validation.py --phase analyze --out results/my_instances --workers 6
```

Новые экземпляры независимы от прежних преобразований по новым
наблюдениям. Они принадлежат прежним восьми семействам функций;
новыми семействами задач они не являются.

### 9.3. Последующие анализы без новых поисков

Следующие команды читают готовые данные статьи и записывают новые
производные отчеты в отдельные каталоги:

```powershell
.\.venv\Scripts\python.exe analyze_ocba_interactions.py --source results/ocba_robustness_20261022 --out results/my_mean_analysis
.\.venv\Scripts\python.exe analyze_ocba_scope.py --out results/my_scope_analysis
.\.venv\Scripts\python.exe diagnose_ocba_traces.py --source results/ocba_instances_smoke_20261022 --out results/my_trace_example --workers 8
.\.venv\Scripts\python.exe audit_ocba_revision.py --out results/my_revision_audit
.\.venv\Scripts\python.exe audit_ocba_hierarchy.py --out results/my_hierarchy_audit
```

`analyze_ocba_interactions.py` проверяет фиксированную сетку статьи;
его нейросетевая часть ожидает 456 парных поисков. Аргумент `--source`
не делает его пригодным для любой новой таблицы.

`analyze_ocba_scope.py`, `audit_ocba_revision.py` и `audit_ocba_hierarchy.py`
используют датированные входы статьи, заданные внутри скриптов.
У них `--out` меняет место новых отчетов, но не выбирает произвольную
новую исходную серию. Нужны сохраненные исходные результаты и промежуточные
анализы, входящие в комплект исследования.

Приведенная команда диагностики восстанавливает только включенный
контрольный пример из трех поисков. Для всех 2880 поисков нужны
полные первичные журналы из отдельного полного архива. В этом минимальном пакете
их недостаточно для восстановления всех поколений. Анализ 99999
бутстреп-перевыборок тоже требует времени, хотя функцию качества заново
не вычисляет.

### 10.1. Общая схема

```text

diagnose_ocba_traces.py
audit_ocba_revision.py
```

## 11. Один поиск внутри движка

### 11.1. Последовательность действий

Главная функция находится в `robust_ocba_engine.py`:

```text
def run_search(task, method: str, seed: int, budget: int,
               event_writer: Callable | None = None,
               pool_writer: Callable | None = None, *,
               swarm_size: int = 6, initial_repeats: int = 3,
               generation_multiplier: int = 6) -> dict:
```

Это сигнатура для ориентации в исходнике, а не самостоятельная программа.
Основной запуск явно передает размеры роя из научной сетки; значение
по умолчанию 6 в функции не означает, что вся расширенная серия имеет M = 6.

Один поиск выполняется так:

1. Создается `Sampler`, знающий остаток бюджета. Отдельно создается
   генератор случайных чисел движения роя.
2. Для каждой частицы выбираются начальная позиция и скорость.
3. Для текущих позиций создаются объекты `Pool`.
4. Выделяется бюджет текущего поколения, не больше оставшегося B.
5. Каждая новая позиция получает начальные измерения.
6. Если остался ресурс, рассчитываются веса распределения и очередная
   порция повторов.
7. По накопленным средним обновляются личные рекорды.
8. Сохраняется глобальный рекорд, рассчитываются новые скорости и позиции.
9. Цикл продолжается до точного исчерпания B.
10. Выбранная точка получает итоговую оценку: истинную для аналитической
    задачи или среднюю по трем новым обучениям для нейросетевой.

При равенстве средних старый личный рекорд сохраняется: принимается
только строго большее новое среднее. Последнее поколение может быть
неполным. Движок не увеличивает B, чтобы завершить его.

После первого поколения движение каждой частицы рассчитывается так:

```text
v_new = 0.729*v + 1.49445*r1*(pbest_x - x) + 1.49445*r2*(gbest_x - x)
v_new = clip(v_new, -0.2, 0.2)
x_new = clip(x + v_new, 0, 1)
```

`r1` и `r2` - новые равномерные случайные числа для координат частиц.
Первое слагаемое сохраняет часть прежнего движения, второе притягивает
к личному рекорду, третье к глобальному. Ограничение скорости сдерживает
скачки, а ограничение позиции удерживает поиск внутри единичного куба.

### 11.2. Что хранит Pool

`Pool` - накопитель наблюдений конкретной созданной точки:

| Поле | Смысл |
|---|---|
| `identifier` | Номер точки внутри данного поиска |
| `x` | Координаты |
| `truth` | Истинное качество аналитической задачи для диагностики |
| `count` | Число измерений |
| `mean` | Их накопленное среднее |
| `m2` | Сумма квадратов отклонений, обновляемая устойчивым алгоритмом |
| `variance` | Выборочная дисперсия `m2/(count-1)` при достаточном числе наблюдений |

Среднее и дисперсия обновляются алгоритмом Уэлфорда. Все прошлые
наблюдения точки не нужно держать в оперативной памяти, хотя сами
измерения записываются в журнал.

Одинаковые координаты при новом посещении не объединяются автоматически:
новая созданная точка имеет новый `pool_id`. Сохраненный глобальный
рекорд, напротив, может повторно использовать тот же объект и его
накопленные наблюдения.

### 11.3. Что делает Sampler

`Sampler` создает точки, выполняет измерения, уменьшает оставшийся бюджет
и передает события функциям записи журналов. Он проверяет, что наблюдение
конечно и что лимит вызовов не превышен.

Движение частиц и шум используют разделенные потоки случайных чисел.
У разных методов внутри условия одинаковые исходные поисковые зерна.
После различных выборов рекордов траектории расходятся. Парность запуска
не означает, что все методы посетили один и тот же набор точек.

### 11.4. Где находится математическое различие методов

`gaussian_star_allocation` получает текущие средние, дисперсии,
индекс лучшего кандидата и пороги личных рекордов. Через скалярную
численную задачу она рассчитывает доли ресурса для PSO-OCBA.

`classic_ocba_allocation` рассчитывает доли обычной OCBA для выбора
лучшего кандидата. Порогов личных рекордов в этой модели нет.

`integer_top_up` переводит вещественные доли в целые дополнительные
количества измерений. Сумма добавок точно равна выделенной порции;
накопленные счетчики не уменьшаются. Нельзя "забрать назад" уже
потраченные наблюдения, даже если новые веса сильно изменились.

В `ocba.py` также предусмотрены численные нижние ограничения для
дисперсий и разностей средних, чтобы близкие или нулевые значения
не приводили к делению на ноль. При фактически нулевых дисперсиях
используется равномерное распределение.

Ключевая гауссова модель использует следующие показатели надежности
сравнений, до применения численных нижних ограничений:

```text
global_rate(i, b) = (mu_i - mu_b)^2 / (2*(var_i/a_i + var_b/a_b))
personal_rate(i) = a_i*(mu_i - threshold_i)^2 / (2*var_i)
```

`mu` - накопленные средние, `var` - оценки дисперсий, `a` - доли
распределения, b - текущий лучший кандидат. Личные показатели
существуют только при наличии сохраненного порога. PSO-OCBA выбирает
положительные доли с суммой 1, максимизируя наименьший показатель
из учитываемых сравнений. Интуитивно это попытка улучшить самое
ненадежное решение. Показатели относятся к гауссовой модели;
они не являются точными вероятностями ошибки при трех наблюдениях
или при произвольном ненормальном шуме.

### 11.5. Что возвращается

Результат `run_search` является словарем одного полного поиска:
выбранная точка, фактические вызовы, итоговое качество, время, число
поколений и диагностические счетчики. Управляющий скрипт добавляет
параметры условия и сохраняет одну строку `runs.csv`.

### 11.6. Что проверяют имеющиеся тесты

Тесты находятся в [`tests`](../tests/test_robust_ocba.py). Среди проверяемых
свойств: точное соблюдение бюджета, неполные последние поколения,
сохранение прежней траектории при параметрах по умолчанию, нормировка
шума, размер сетки, целые добавки, парность статистики, сохранение
исторического входа и запрет смешения протоколов.

Общий запуск набора тестов:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

В комплект включены необходимые научные тесты. Их выполнение не заменяет проверку фактических журналов и статистических предпосылок.

## 12. Нейросетевая часть по шагам

MLP (Multilayer Perceptron, многослойный персептрон) здесь представляет
собой небольшую сеть с одним скрытым слоем. HPO (Hyperparameter
Optimization, оптимизация гиперпараметров) выбирает настройки обучения.

### 12.1. Входные данные и разделение выборок

Используются Ionosphere: 351 объект, 34 признака, и Sonar: 208 объектов,
60 признаков. Для каждого набора фиксированы три разбиения со случайными
зернами 7101, 7102 и 7103.

Разбиение стратифицировано: сохраняются пропорции классов с учетом
целочисленного округления. Около 60% объектов используются для обучения,
20% для проверки конфигураций, 20% для итогового теста.

Во время поиска `StandardScaler` обучается только на обучающей части.
Тестовая часть не используется для выбора конфигурации. После выбора
итоговая модель обучается на объединении обучающей и проверочной частей;
для него масштабирование признаков также оценивается заново только
на этом объединении.

Это предотвращает утечку данных (использование информации итогового теста
на этапе настройки). Три разбиения одного набора перекрываются и
не превращаются в три независимых набора данных.

### 12.2. Какие параметры ищет рой

Позиция частицы имеет три координаты `x[0]`, `x[1]`, `x[2]` в `[0, 1]`.

| Координата | Декодирование | Значения |
|---|---|---|
| `x[0]` | `16*rint(1 + 7*x[0])` | 16, 32, 48, 64, 80, 96, 112 или 128 скрытых нейронов |
| `x[1]` | `10**(-4 + 2.5*x[1])` | Скорость обучения от 0.0001 до примерно 0.03162 |
| `x[2]` | `10**(-6 + 4*x[2])` | Коэффициент L2-регуляризации от 0.000001 до 0.01 |

`rint` округляет до ближайшего целого; затем результат умножается на 16.
Поэтому пространство ширины слоя дискретное. Точное преобразование
с ограничением диапазона находится в `TabularNNObjective.decode`.

Фиксированы активация ReLU (Rectified Linear Unit, функция выпрямления),
оптимизатор Adam (Adaptive Moment Estimation, адаптивная оценка моментов),
размер мини-пакета 64 и 20 эпох. Эпоха - один проход обучения по
обучающей выборке. Автоматическая ранняя остановка не включена.

### 12.3. Откуда берется шум

Одна и та же конфигурация с разными зернами обучения может получить
разную accuracy (долю правильных ответов). Причины включают случайную
инициализацию весов и порядок обучающих примеров. Эта случайность
является частью измеряемого процесса.

Для основного нейросетевого сравнения M = 12 и B = 540. Сравниваются
PSO, PSO-EA и PSO-OCBA. Контроль OCBA-RS в этой серии не запускался.

### 12.4. Как устроено планирование объема

1. На каждом из шести сочетаний "набор и разбиение" выполняются
   24 независимых пилотных поиска каждого из трех методов.
2. Для двух сравнений OCBA с контролями на каждом сочетании получаются
   12 выборок парных разностей.
3. По их разбросу строятся верхние модельные границы стандартного
   отклонения. Пилотный средний выигрыш не используется для выбора объема.
4. Для эффекта 0.01 accuracy, то есть одного процентного пункта,
   подбирается объем с плановой мощностью 90%.
5. Используются нецентральное t-распределение и симуляционные проверки
   на нормальной, тяжелохвостой и центрированных пилотных моделях.
6. Выбранный объем проверяется отдельно новыми случайными симуляциями
   в `validate_robust_power.py`, без изменения объема и без главных данных.
7. Только после этого выполняется подтверждающая серия новыми зернами.

Кандидаты объема: от 48 до 1536, кратные 24. Для статьи получено 456.
В пилоте было 432 поиска, в подтверждающей серии 8208:
`2 набора * 3 разбиения * 3 метода * 456`.

90% относится к модельной вероятности обнаружить заданный эффект
отдельным сравнением при консервативном уровне `0.05/12`. Это не
вероятность, что все 12 сравнений станут значимыми, и не гарантия
значимости фактически наблюдаемого эффекта.

### 12.5. Как получается итог одной строки

После 540 поисковых обучений выбирается одна конфигурация. Она обучается
на объединенной обучающей и проверочной части три раза с новыми зернами.
`final_score` - среднее трех долей правильных ответов на тестовой части.

У Sonar тестовая часть содержит 42 объекта. Один дополнительный верный
ответ в одном из трех итоговых обучений меняет их среднюю accuracy
на `1/(3*42)`, то есть примерно 0.794 процентного пункта.

Большое число поисковых зерен позволяет точнее оценить среднее для
фиксированного разбиения. Оно не увеличивает число независимых тестовых
объектов и не устраняет неопределенность переноса на другие данные.

`runs` и `run` различаются: `runs` описывает плановое число поисковых
повторов в задании; `run` идентифицирует конкретную строку-повторение.

Особенно важно не подменять `final_score` полем `selected_observed_score`.
Второе уже участвовало в выборе победителя и может быть оптимистично
завышено шумом. Для сравнения итогов методов используется `final_score`.

## 15. Статистика без подмены исследовательских вопросов

### 15.1. Почему сравнение парное

Внутри условия методы сопоставляются по номеру поискового запуска.
Для каждого s рассчитывается разность:

```text
D_s = Q_OCBA,s - Q_baseline,s
```

Положительное значение означает преимущество OCBA. Для сравнения форм
шума сначала берутся такие разности методов при каждом шуме, затем
разность этих эффектов. Сравнение только качества OCBA при двух шумах
отвечало бы другому вопросу.

Вектор результатов одного зерна по связанным условиям сохраняется
целым при перевыборке. Восемь функций основной серии фиксированы;
648 ячеек не рассматриваются как 648 независимых случайно выбранных
семейств задач.

### 15.2. Семьи сравнений

Семья - заранее определенный для конкретной процедуры набор проверяемых
сравнений. Если выполнить очень много отдельных тестов без поправки,
случайные малые p-значения встретятся даже без эффекта.

| Семья | Число | Статус | Процедура |
|---|---:|---|---|
| Расширенная OCBA против PSO и EA | 1296 | Основная семья протокола серии | Двусторонний Wilcoxon, общая поправка Holm |
| Расширенная OCBA против OCBA-RS | 648 | Отдельная вторичная семья | Двусторонний Wilcoxon, отдельная Holm |
| Контрасты формы шума, взаимодействий и средних | 23 | Последующий исследовательский анализ | Одношаговый совместный max-t bootstrap |
| Контрасты абляции n0 | 72 | Исследовательская абляция | Отдельный совместный max-t bootstrap |
| Нейросетевые средние против нуля | 12 | Подтверждающая серия после независимого пилота | Парный t-критерий, Holm |
| Нейросетевые средние против 0.01 | 12 | Последующая исследовательская проверка порога | Односторонний t-критерий, отдельная Holm |
| Проверка новых экземпляров | 5 | Локальный план до новых наблюдений; вопрос выбран по прежним данным | Отдельный совместный max-t bootstrap |
| Исключение каждого семейства новых экземпляров | 40 | Последующая чувствительность | Совместный max-t для `8*5` контрастов |
| Иерархический сценарий новых экземпляров | 5 | Последующая чувствительность к обобщению | Перевыборка семейств, экземпляров и зерен, studentized max-t |

Исторические семьи исходной версии, включая основную 384, отделены
от расширенной серии. Анализ чувствительности критерием знаков также
не заменяет исходную семью Wilcoxon. Весь проект не образует одну
общую процедуру с единой гарантией ошибки для всех когда-либо заданных
исследовательских вопросов.

### 15.3. Что проверяют Wilcoxon и критерий знаков

Критерий Уилкоксона использует знаки и ранги абсолютных парных разностей.
Стандартная интерпретация требует внимания к симметрии их распределения.
Он не является общим тестом среднего для произвольного асимметричного
распределения.

Код использует `scipy.stats.wilcoxon` с `zero_method="wilcox"`
и `method="auto"`. Нулевые разности исключаются из рангового расчета,
но полностью нулевое сравнение получает p = 1 и сохраняется в семье
поправки Holm. Для непрерывного качества разности округляются до
12 десятичных знаков, чтобы шум сериализации не создавал искусственных
различий. Для решетчатой accuracy при соответствующем анализе могут
использоваться целые количества правильных ответов.

Точный, перестановочный или аппроксимационный режим определяется SciPy
с учетом размера выборки, нулей и связок. Версия библиотеки поэтому
является частью воспроизводимости.

Дополнительный точный критерий знаков использует число положительных
и отрицательных разностей. Ему не нужна симметрия величин разностей,
но он проверяет баланс знаков, а не среднее качество. Совпадение двух
выводов усиливает устойчивость описания, не превращая их в тест среднего.

### 15.4. Что означает описательный критерий ячейки

В таблицах подсчитываются ячейки, где одновременно:

```text
Holm-adjusted p < 0.05
и
точечная средняя разность >= 0.02
```

Первое условие относится к ненулевому ранговому отличию, второе
к величине наблюдаемой средней разности. Вместе они не являются
статистическим доказательством, что истинный средний эффект больше 0.02.
Поэтому используется название "число ячеек с описательным критерием".

Для прямого вывода о превышении порога нужна процедура для среднего
относительно этого порога. В анализе средних используется, в частности,
сравнение нижней совместной доверительной границы с 0.02.

### 15.5. Какие именно 23 контраста считаются

Сначала задается `D = Q_OCBA - Q_EA` для ненулевого шума. Все неуказанные
ниже оси усредняются равномерно по исследованной сетке.

| Тип | Число | Определение |
|---|---:|---|
| Форма шума | 3 | `mean(D_noise - D_gaussian)` для каждого ненормального шума |
| Взаимодействие формы с бюджетом | 6 | Для каждого ненормального шума изменение `D_noise - D_gaussian` при B = 2160 или 8640 относительно B = 540 |
| Взаимодействие формы с роем | 6 | Для каждого ненормального шума изменение `D_noise - D_gaussian` при M = 12 или 24 относительно M = 6 |
| Взаимодействие формы с eta | 3 | Для каждого ненормального шума изменение `D_noise - D_gaussian` при eta = 2 относительно eta = 1 |
| Средние по распределениям | 4 | `mean(D)` отдельно при каждом распределении |
| Общее среднее `mean_all` | 1 | Равномерное среднее D по четырем распределениям и всем ненулевым условиям |

Итого `3 + 6 + 6 + 3 + 4 + 1 = 23`.
Каждое среднее распределения агрегирует 144 условия:
`8 функций * 2 уровня * 3 роя * 3 бюджета`. Общее среднее агрегирует 576
ненулевых условий. Нулевая контрольная серия сюда не входит.

Точные спецификации находятся в `contrast_specs` и `make_contrasts`
модуля `analyze_ocba_interactions.py`. Внутренний аудит также сохраняет
развернутые веса контрастов.

### 15.6. Как работает совместный max-t bootstrap

Bootstrap (бутстреп, повторная выборка из наблюденных данных) оценивает
изменчивость статистики при многократной перевыборке исходных наблюдений.
Здесь он используется со стратификацией по фиксированным задачам
и сохранением парных векторов зерен.

Схема основного расчета средних:

1. Для каждой функции и каждого поискового зерна формируется полный
   вектор контрастов.
2. Внутри каждой фиксированной функции зерна перевыбираются с возвращением.
   Все компоненты выбранного вектора перемещаются вместе.
3. Рассчитываются средние и стандартные ошибки перевыборки.
4. Для каждого контраста берется модуль центрированной ошибки,
   деленной на его стандартную ошибку перевыборки.
5. Сохраняется максимум по всей семье. Отсюда название max-t.
6. Квантиль 0.95 этих максимумов умножается на исходные стандартные
   ошибки для построения совместных интервалов.

Используется 99999 перевыборок. Это одношаговая centered studentized
процедура: ошибки центрированы, нормированы оценкой стандартной ошибки,
гипотезы последовательно не удаляются. Ее нельзя описывать как
реализацию ступенчатого алгоритма Romano-Wolf.

Совместное покрытие и контроль FWER (Family-Wise Error Rate, вероятности
хотя бы одной ошибки первого рода в семье) являются бутстреп-приближением.
Это не точная конечновыборочная гарантия при любом законе данных.

Интервал одной ячейки и совместный интервал среднего по сетке отвечают
разным вопросам. Поэтому положительное среднее при нормальном шуме
совместимо с малым числом отдельно значимых ячеек.

Условие "нижняя совместная граница выше 0.02" использует двустороннюю
совместную 95% область консервативно для направленного вывода. Прохождение
порога общим `mean_all` само по себе не означает прохождения порога каждым
распределением: сильные ненормальные эффекты повышают общее среднее.

### 15.7. Почему два интервала для новых экземпляров различаются

Основная проверка новых экземпляров удерживает 16 выбранных задач
фиксированными и оценивает неопределенность по поисковым зернам.
Для контраста "логнормальный минус нормальный" получается приблизительно
`1.1668 [0.9621; 1.3714]`.

Последующий иерархический сценарий перевыбирает также семейства функций
и экземпляры внутри семейств. Он дает `[-3.0175; 5.3511]`.
Это другая модель изменчивости, а не ошибка вычитания двух средних.

Всего восемь семейств выбраны целенаправленно. Их неоднородность и
малые стандартные ошибки отдельных перевыборок делают нормированный
максимум нестабильным: критический множитель около 7.50. Положительные
процентильные квантили самих средних `[0.3086; 2.3424]` не являются
использованным совместным интервалом.

Иерархический результат оставлен анализом чувствительности.
Он не объявляется популяционным доверительным интервалом для всех
возможных задач оптимизации. Более узкая конструкция после просмотра
данных вместо исходной не выбиралась.

### 15.8. Что означает MDE90

MDE (Minimum Detectable Effect, минимально обнаружимый эффект) здесь
оценивается после наблюдений для контрастов с размером роя. В эмпирической
модели к целевому среднему добавляется гипотетический аддитивный сдвиг
при фиксированном законе центрированных ошибок и критическом множителе
семьи 23. MDE90 - сдвиг, обнаруживаемый в 90% этих симуляций.

Диапазон около 0.278-0.355 является условной описательной оценкой.
Это не заранее рассчитанная мощность исходной синтетической серии
и не свидетельство отсутствия меньших эффектов.

### 15.9. Что проверяет внутренний аудит

Другая арифметическая реализация восстанавливает 1944 ранговых
сравнения, 12 основных нейросетевых сравнений и семейства bootstrap
23 и 72. Для сопоставления bootstrap намеренно используются тот же
алгоритм генератора NumPy, зерна, размеры блоков и порядок индексов.

Независимо написана арифметика, а не случайная выборка. Поэтому
расхождение менее `2e-15` относится к вычислению на одинаковых
перевыборках. Это не совпадение двух независимых симуляций и не
доказательство статистических предпосылок.

### 16.1. Основная сетка

| Контраст на фиксированных 16 экземплярах | Средний эффект | Совместный 95% интервал |
|---|---:|---|
| OCBA минус EA, нормальный шум | 0.1309 | [0.0398; 0.2220] |
| OCBA минус EA, логнормальный шум | 1.2977 | [1.1084; 1.4869] |
| Логнормальный минус нормальный эффект | 1.1668 | [0.9621; 1.3714] |
| OCBA минус OCBA-RS, нормальный шум | -0.1223 | [-0.2221; -0.0226] |
| OCBA минус OCBA-RS, логнормальный шум | -0.2195 | [-0.3058; -0.1333] |

Выбранное различие эффектов воспроизведено на новых преобразованиях
тех же восьми семейств при M = 12, B = 8640, eta = 2.
Перенос на произвольную новую функцию не установлен; иерархический
сценарий из раздела 15 включает ноль.

Относительно OCBA-RS в основной семье из 648 сравнений нет ячеек
с описательным положительным критерием и есть 11 значимых проигрышей.
В новой фиксированной серии среднее качество OCBA также ниже OCBA-RS
при обоих шумах. Это не доказывает универсальное доминирование RS.

### 16.3. Абляция и диагностика рекордов

Абляция n0 не установила значимого изменения эффекта при переходе
от 3 к 5 или 10 стартовым измерениям в проверенных условиях.
Отсутствие установленного изменения не доказывает эквивалентность
и не идентифицирует механизм выигрыша.

В диагностике новых экземпляров при логнормальном шуме:

| Метод | Доля ошибок pbest | Доля ошибок gbest |
|---|---:|---:|
| EA | 42.28% | 94.80% |
| OCBA | 35.37% | 83.34% |
| OCBA-RS | 36.20% | 81.06% |

Ошибка pbest - неверное принятие худшей новой точки или неверное
отклонение лучшей по истинному качеству. Знаменатель включает сравнения
с уже существующим личным рекордом; первая установка рекорда не входит.
Различия меньше допуска `1e-12` не учитываются как строгие ошибки.

Ошибка gbest фиксируется, если выбранный по наблюдаемому среднему
глобальный рекорд хуже по истинному качеству лучшего из сохраненных
личных рекордов. Знаменатель - число поколений. Это не сравнение
со всеми точками, когда-либо посещенными поиском.

У OCBA меньше ошибок pbest, чем у RS, но больше ошибок gbest и хуже
итоговый regret: примерно 0.815 против 0.596. Различные методы посещают
разные точки. Эти описательные связи не являются причинным
доказательством механизма.

### 16.4. Нейросетевой результат

В подтверждающей серии 4 из 12 сравнений среднего против нуля значимы,
но практически значимого положительного преимущества не установлено.
Последующие односторонние проверки среднего против 0.01 не дали
отклонений нулевой гипотезы после Holm. Верхние одновременные границы
ниже 0.01 в 11 из 12 сравнений, включая все шесть сравнений с EA.

Вывод относится к двум табличным наборам, малому MLP и фиксированным
разбиениям. Он не доказывает нулевой эффект и не распространяется
автоматически на другие архитектуры или HPO в целом.

### 16.5. Как правильно сформулировать общий результат

На исследованных задачах полезность повторов и адаптивного распределения
зависит от формы шума, бюджета и конкретного контроля. Учет личных
рекордов не показал преимущества над обычной OCBA выбора лучшего.
Универсальный закон, причинный механизм и ускорение при одинаковом
реальном времени не установлены.

## 17. Проверка минимального комплекта

Передаются текущая статья, приложения А-З, английский README, это руководство,
необходимый научный код, фиксированные зависимости, данные поисков и планы.
Документы прошлых редакций и история подготовки публикации не включаются.

```powershell
py -3.13 verify_reviewer_package.py
.\.venv\Scripts\python.exe verify_reviewer_package.py --recompute
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Первая команда использует стандартную библиотеку и проверяет содержимое
по `reviewer_package_manifest.json`. Для второй и третьей сначала установите
`requirements.txt` в Python 3.13.3 согласно разделу 6.

Проверяются результаты всех 126720 поисков и отдельные первичные примеры,
но все 351216000 наблюдений не проигрываются. Сохраненные диагностические
траектории сверяются с итоговыми качествами и счетчиками ошибок.
Пересчет таблиц не является новым выполнением всех поисков.

Полные первичные трассы находятся в сохраненном отдельном
`ocba_reviewer_full_20261024.zip`. Он нужен для дополнительного аудита
каждого измерения, но не для приведенного пересчета статистики.

Для проверки и распаковки нового минимального ZIP:

В версии GitHub сначала распакуйте весь репозиторий и выполните `py -3.13 prepare_data.py`.

Назначение должно быть новым каталогом. Отчеты создаются под
`reviewer_checks`; входные данные статьи не изменяются. Контрольные суммы
и результаты внутреннего пересчета не объявляются внешним независимым
воспроизведением.

## 18. Как менять эксперимент корректно

### 18.1. Где задаются параметры

| Что требуется изменить | Где находится |
|---|---|
| Список функций, исходные формулы и масштабы | `ocba_benchmarks.py`: `FUNCTIONS`, `SPANS`, `raw_loss` |
| Семейства шума | `run_robust_ocba_study.py`: `NOISES`, `RobustBenchmark.draw_from_truth` |
| Рои, бюджеты, методы | `SWARMS`, `BUDGETS`, `SYNTH_METHODS`, `NN_METHODS` и `jobs` |
| Начальные повторы и бюджет поколения | `robust_ocba_engine.run_search`; вызывающий код и описание протокола |
| Коэффициенты движения частиц | `robust_ocba_engine.py` |
| Правило распределения | `ocba.py` |
| Нейросетевые данные и разбиения | `NN_DATASETS`, `NN_SPLITS`, `load_real` |
| Декодирование и архитектура MLP | `TabularNNObjective` в исторической реализации; для новой версии нужна отдельная сохраняющая историю реализация |
| Объем и допущения планирования | `plan_robust_nn_power.py` и соответствующий протокол |
| Определение контрастов средних | `contrast_specs`, `make_contrasts` |

Научная сетка согласована также с анализаторами, тестами полноты и
числом сравнений. Изменение одного списка без пересмотра остальных
частей не создает корректную новую серию автоматически.

### 18.2. Последовательность новой версии

1. Сформулируйте конкретный вопрос, метрику и единицу обобщения.
2. Сохраните прежние исходники и результаты. Каталог `historical`
   не редактируйте для изменения текущего эксперимента.
3. Измените согласованно исполнение, описание протокола и проверку
   ожидаемой сетки. Для нового варианта нейросети вынесите реализацию
   из исторического снимка в новую версию.
4. Определите семьи сравнений и практические пороги до новых наблюдений.
5. Проверьте короткий технический пример, бюджет и учет единиц.
6. Используйте новый каталог вывода и новый зафиксированный протокол.
7. Сохраните первичные наблюдения, окружение и контрольные суммы.
8. Отличайте новые подтверждающие вопросы от анализа уже просмотренных
   данных. Новая дата файла сама по себе не делает анализ подтверждающим.

### 18.3. Как читать временные показатели

`search_seconds` и `allocation_seconds` измеряются внутри одного поиска.
`complete.json["seconds"]` - длительность рабочего задания. Сумма таких
длительностей при параллельной работе не равна времени ожидания всего
запуска и не является процессорным временем.

В статье время дополнительных основных частей суммировалось из исходных
измерений. Складывать уже округленные значения из текста менее точно.
При сравнении скорости нужно отдельно проектировать эксперимент
с одинаковым реальным временем, оборудованием и способом учета затрат.

## 19. Частые проблемы

| Симптом | Причина и действие |
|---|---|
| `ModuleNotFoundError` | Вызван другой Python или не установлены зависимости. Используйте интерпретатор конкретного окружения и его `-m pip` |
| `py -3.13` не найден | В системе нет соответствующего Python Launcher или установленной ветки. Проверьте существующую установку; используйте путь к ее Python 3.13 |
| Не запускается `Activate.ps1` | Активация не нужна: вызывайте `.venv\Scripts\python.exe` напрямую |
| Основной запуск не принимает `--budget` | Это аргумент старого пилота, текущая сетка зафиксирована. Для старого сценария используйте `legacy` |
| Каталог пробы не принимается | Его имя должно содержать `smoke`; не используйте тот же каталог для научного запуска |
| `Protocol, sources or smoke mode changed` | Изменились научные исходники, параметры или режим. Нужен соответствующий исторический снимок либо новый каталог |
| `Refusing to freeze a nonempty directory without a protocol` | Каталог уже содержит посторонние данные. Выберите новый пустой каталог |
| `Dataset checksum mismatch` | CSV отличается от своего manifest. Восстановите вход из исходного комплекта, не переписывайте контрольную сумму ради обхода проверки |
| `Frozen power plan does not match protocol, pilot or code` | План относится к другим входам. Продолжайте неизменный расчет или создавайте новую серию с собственным независимым пилотом |
| `Independent validation must precede NN main data` | Нарушен порядок валидации и главной серии. Нельзя исправлять это фиктивным файлом валидации задним числом |
| `Power plan is already frozen` | Планировщик вызван напрямую повторно. Основной вход `experiment.py` проверяет и использует готовый план |
| В `--dry-run` нейросетевой объем равен `null` | Это ожидаемо до независимого планирования объема |
| Статистика сообщает неполную сетку | Не все задания закончились, есть дубликаты либо выбран технический каталог. Сначала проверьте завершение соответствующей серии |
| Полный проверяющий скрипт не находит корневой manifest | `--recompute` вызван в рабочем дереве, а не в распакованном комплекте. Проверьте ZIP через `--archive` или перейдите в распаковку |
| Нет первичных `.csv.gz` в компактном комплекте | Для всех трасс нужен полный архив |
| Старый аудит ищет путь с диском автора | Сохранен кеш с абсолютными путями. Для комплекта используйте его проверяющий скрипт; для нового расчета создавайте собственный новый каталог |
| Повторы прогресса после продолжения | Журнал добавляется в конец. Считайте уникальные задания, а не сумму всех строк журнала |
| Нейросети работают заметно дольше синтетики | Один вызов содержит обучение, а не простую формулу. Число вызовов и их стоимость различаются |
| Различаются только временные поля | Время зависит от машины и текущей нагрузки. Оно не обязано побитово повторяться при одинаковых научных зернах |

При диагностике сначала выясните точную команду, используемый Python,
каталог `--out`, фазу и последнее сообщение об ошибке. Полезные входы:
`protocol.json`, `runtime_environment.json`, `power_plan.json`,
`power_validation.json` и `complete.json` проблемного задания.

## 20. Словарь и порядок чтения исходников

| Термин | Значение в этом проекте |
|---|---|
| Accuracy | Доля правильных ответов; обычно хранится числом от 0 до 1 |
| Процентный пункт | Абсолютное изменение доли на 0.01; отличается от относительного изменения на 1% |
| Regret | Потеря истинного качества относительно известного оптимума |
| Ресэмплинг | Повторные измерения точки; в статистике слово также употребляется для перевыборки наблюдений, поэтому контекст важен |
| Bootstrap | Статистическая перевыборка уже полученных наблюдений без нового запуска оптимизатора |
| Контраст | Заданная разность или взвешенное среднее эффектов |
| Страта | Фиксированная группа задач, внутри которой перевыбираются поисковые зерна |
| Стандартная ошибка | Оценка изменчивости статистической оценки, например среднего, а не разброс отдельных результатов |
| Точечный интервал | Интервал отдельного эффекта без совместного покрытия всей семьи |
| Совместный интервал | Компонент области, рассчитанной с учетом всей заданной семьи сравнений |
| Подтверждающая проверка | Проверка зафиксированного вопроса на данных, не использованных для его выбора |
| Исследовательский анализ | Анализ, вопросы или детали которого сформированы после просмотра прежних данных |
| Внешняя валидность | Основания переносить результат за пределы изученных задач |
| Manifest | Перечень файлов и их контрольных сумм или происхождения |
| Smoke test | Короткая проверка исполнения без научного вывода |

Рекомендуемый порядок чтения кода:

1. `experiment.py`: увидеть весь порядок фаз.
2. `run_robust_ocba_study.py`: понять сетку, протокол и запись результата.
3. `ocba_benchmarks.py`: понять, что именно оптимизируется.
4. `robust_ocba_engine.py`: проследить один поиск от начала до конца.
5. `ocba_engine.py`: разобраться с накоплением наблюдений и бюджетом.
6. `ocba.py`: изучить математическое распределение ресурса.
7. `TabularNNObjective`: понять нейросетевое измерение и итоговое тестирование.
8. `study_statistics.py`, `paired_mean_inference.py`: разделить ранговый
   анализ, парные средние и совместные интервалы.
9. Анализаторы нужной дополнительной серии и соответствующие тесты.

Для защиты результата перед рецензентом полезно уметь проследить
одну цепочку полностью: строка шумного наблюдения -> накопленное среднее
точки -> выбранный рекорд -> итог одного поиска -> парная разность ->
контраст заданной семьи -> интервал и ограниченный областью данных вывод.
